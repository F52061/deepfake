# exp_1：第一层诊断——互补错误是否存在

## 当前状态

本文件夹只进行冻结预测的统计，不修改或训练外部模型架构，不运行 G29/G30、不训练门控。当前没有导入真实配对预测，故没有真实统计结论；自检产生的合成数字不得写为研究结果。

## 验证目的

同一张评测图像由独立改进 ViT 与 CLIP-only 检测读取器各自预测，固定源域阈值后统计四组：两路都对、ViT 错 CLIP 对（潜在救回）、ViT 对 CLIP 错（潜在误伤）、两路都错。

这回答“第二分支有没有潜在补救机会”，不回答“能否在推理时选出机会”或“融合能否提升”。本轮不做人为削弱 ViT、不使用真实标签设计选择器，不从错误子集中计算可泛化的 AUC。

## 预测准备（统计器不代替推理或读取器训练）

1. ViT 使用 `acc.txt` 对应权重的原生头；或者明确声明为仅输入 ViT CLS 的独立探针。严禁使用完整融合检测器 logits 代替 ViT-only 分数。
2. CLIP image 本身不提供真假分类头，须先用 FF++ 训练分组拟合独立 CLIP-only 读取器。仅源域选参；保存读取器参数、标准化和层位，不能使用目标标签拟合。两路均对同一图像预测。
3. 本版采用独立源域验证集确定阈值：该验证集的视频及关联伪造均不能参与读取器/检测器拟合；另外保留源域 test、CD2/DFDCP/Wild test 作评测。训练内预测不进入本轮。
4. 若现有原生 ViT 已看过所有候选源验证视频，不能只重新划分帧解决；应找真正未用于训练的视频，或另行设计视频级交叉拟合。当前脚本不把 OOF 预测冒充独立验证预测。
5. 标签统一 `0=real,1=fake`，分数越大越假。原工程输出类别顺序需要从训练定义确认，不能根据目标 AUC 反转。每路沿用自身预处理，但跨域固定，并在来源文件记录。
6. `video_id` 必须是真实视频身份，不得用人物 ID、帧号代替；`group_id` 是独立重采样单元，FF++ 的同原始视频及关联伪造应合并（涉及两个原视频时需避免关联跨划分）。评测与校准不能跨 group，训练隔离还需人工审计。仅字符串检查不能证明无泄漏。

## 输入契约

一份 `paired_predictions.npz` 包含等长一维数组：

| 字段 | 含义 |
|---|---|
| row_id / path | 唯一样本身份、图像路径；顺序为两路严格配对后的同一顺序 |
| domain | ffpp / cd2 / dfdcp / wild；其他域可单列 |
| split | val 或 test；仅 ffpp 可 val，不接受训练内分数 |
| video_id / group_id | 真实视频身份和独立关联分组 |
| y | 0 真实、1 伪造 |
| vit_score / clip_score | 两路独立预测的连续分数，越高越假 |

NPZ 不接受 object 类型，字符串存为 Unicode 数组。不能只提交 `acc.txt` 或各域汇总 JSON。统计器不会从不同文件猜测行对齐。

另外提供已填写的 `provenance.json`，模板为 `provenance.example.json`。填写实际 checkpoint SHA256、预处理、训练/选模历史、分数定义并完成视频身份审计后才能运行。上游目标选模偏差不能因为本轮 source-only 校准而消失；默认研究为探索性。模板中的 false 是待核对状态，不是建议绕过检查。

## 阈值与统计

两路各自只按 ffpp/val 的 balanced accuracy 选阈值，同分优先靠近零、再选择较小阈值；在所有 test 域固定。由于类别顺序和尺度可能不同，不默认两路都取零。

逐域报告四组数量、比例、真实/伪造分布、视频和关联 group 覆盖；ViT 与 CLIP AUC、CLIP−ViT AUC 差、正确率、分歧比例、ViT 错误中的潜在救回比例，以及原本正确中的潜在误伤比例。`rescue−harm` 反映把所有预测换成 CLIP 时的正确率差，不是选择性融合的实际收益。

使用域内关联 group 配对 bootstrap，默认1000次，每次同时重采样两路；宏平均只用 CD2/DFDCP/Wild，缺域标记 incomplete，不自动替换。CD1 若提供只单列，不作为独立主域。视频覆盖可重叠，不得把四组视频数相加。只有一个独立 group 不给区间，单类重采样不计算 AUC，报告有效次数；CI 条件于固定模型和阈值，不覆盖训练及校准不确定性。

真实标签选择的 oracle 只报告正确率 `P(ViT正确或CLIP正确)`，明确不可部署，不通过拼接两路分数报告虚构 oracle AUC。

## 执行

在项目根目录、具有 NumPy 的环境中运行（无需加载 PyTorch 或 sklearn）：

```powershell
python vit_module/exp_1/check_exp_1.py
python vit_module/exp_1/analyze.py `
  --input vit_module/exp_1/paired_predictions.npz `
  --provenance vit_module/exp_1/provenance.json `
  --output vit_module/exp_1/results/run01 `
  --source ffpp --primary-domains cd2 dfdcp wild `
  --bootstrap 1000 --seed 20261012
```

上述真实输入目前尚未创建，不能把该示例视为已可运行的真实实验。输出只能在本实验文件夹内创建新子目录，拒绝覆盖已有目录。准备好输入后，执行前核对 provenance，执行后先读统计文档，再核对逐样本数据。

## 结果怎么决定后续

- 救回很少或仅集中在个别视频：没有足够证据支持复杂选择模块。
- 多域存在救回机会：只支持进入第二层“推理反馈能否识别机会”的研究；即使 CLIP 总体更差也可能存在局部机会。
- 救回存在但误伤也很多：不能直接增加 CLIP 权重，需检验选择规则是否优于相同开启率的随机选择。
- CI 跨零不意味着两个分支等价；本轮 AUC 差也不等于融合增量。

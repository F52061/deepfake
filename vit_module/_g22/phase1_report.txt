                                          -> 其 mean4dom = 0.8318

                                          -> mean4dom = 0.8191
        差 = -0.0127。cd1 -0.0244, cd2 -0.0204, wild -0.0177 变差;
        dfdcp +0.0118 变好。
      这个方向是**可以解释的**: 桥是死的 => 分类头 output 实际只作用在
      [clip_vision_cls*alpha_v(768), 常数(128), vit_feats(768)] 上，128 维桥输入

      score = (W1-W0)·features + (b1-b0)，而 features[768:896] 对所有图片是

      = 0.03327417（实测计算，dW[768:896] 的范数 = 0.022210）。
      常数平移不改变任何排序，AUC 是 rank-based
      => **把桥整个删掉，R0 的 6 个 AUC 会一模一样。**
      死桥对 R0 AUC 是"天然不可见"的。这解释了为什么 R0 看起来还挺正常。

§5.1  【新发现】整个 CLIP 文本分支在 forward 中是死代码，梯度恒为 None
    证据 A（静态，vit_m2f2_detector_bridge.py）:

    证据 B（动态）: Task2 探针中 text_proj[0].weight.grad = None，
        clip_text_encoder.prompt_tokens.grad = None（尽管
        requires_grad 被显式设为 True 且被放进 optimizer，lr=1e-3）。
    影响:
      * prompt_tokens 被列为"可训练参数"，永远不会有梯度 => 从未被更新。

§5.2  未修改模型在 FF++ 真实训练图上 loss=6.65，把"真"高分判成"假"

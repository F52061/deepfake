    per-domain: cd1:0.6430 vs 0.6430 cd2:0.6220 vs 0.6220 dfdcp:0.6003 vs 0.6003 ffiw:0.5889 vs 0.5889 wild:0.6333 vs 0.6333

    swapped AUC is EXACTLY EQUAL to the main AUC (not 1-AUC), for cs_alpha and cs_mean alike.
    This is mathematically forced, not a bug, and it was verified explicitly:
      StandardScaler().fit_transform(-X) == -StandardScaler().fit_transform(X): max dev = 0.0e+00
      refitted LR coefficients: coef(swap) + coef(main) max abs dev = 0.0e+00;
      intercepts main=0.057575 swap=0.057575  ->  df_swap(-x) == df_main(x) exactly
    Why: cs_alpha_swap = -cs_alpha, i.e. the swap is a global reflection of the feature space applied
    to BOTH classes.  For any score function s, P(s(-x_fake) > s(-x_real)) = P(s(x_fake) > s(x_real)),
    so the separating power of the class-conditional distributions is reflection-invariant.  The
    scaler flips sign exactly, the L2-regularised logistic optimum flips its coefficient vector
    exactly (the intercept is unchanged), hence df_swap(x') = df_main(x) pointwise and the AUC is
    preserved to machine precision rather than mirrored.
    CONSEQUENCE FOR THE CONTROL'S STATED PURPOSE: this arm does NOT discriminate sign/direction.
    What it does establish is that the feature construction is exactly antisymmetric, so no result
    here can be an artefact of which prompt was placed in the 'real' vs 'fake' slot.  Note the control
    does have teeth when the construction is NOT a pure negation: cs_cat is not antisymmetric
    (mean4dom 0.6552 vs 0.6877 swapped), and there the numbers do move.
    The controls that genuinely probe whether the signal is SEMANTIC are the NULL and RANDOM arms;
    both collapse to ~chance (table above), which is the informative negative result.

CAVEATS (honest)
----------------------------------------------------------------------------------------------------
  1. LINEAR-REACHABILITY LOWER BOUND.  The cross-domain AUC is a StandardScaler + LogisticRegression
     (C=1e-3) head fitted on FF++ train only and applied unchanged to each target domain.  It
     measures how much real/fake signal is LINEARLY AVAILABLE in the frozen feature.  A non-linear
     head, a recalibrated head, or any fine-tuning could extract more.  A low number does NOT prove
     the signal is absent, only that it is not linearly reachable by this protocol.
  2. 300 IMAGES PER TARGET DOMAIN IS SMALL.  At AUC ~0.85 with n=300 the per-domain standard error
     is roughly 0.02-0.03, and the within-domain class balance constrains it further.  Per-domain
     differences below ~0.05 should not be over-read.  mean4dom averages 4 domains, which helps
     but does not remove this.
  3. THIS DOES NOT PROVE AN END-TO-END DETECTOR WOULD EXPLOIT THE SIGNAL.  Correlation is not
     causation: a frozen feature carrying alignment information says nothing about whether a
     trained detector routes it into the decision.  The defect under study (text features computed,
     projected, then discarded) is an ARCHITECTURAL fact, independent of this probe.
  4. THE PROMPTS ARE FIXED AND PRE-REGISTERED (3 real / 3 fake / 1 null), chosen before any result
     was seen, so no prompt search was performed; conversely, prompt engineering could plausibly
     change the numbers, and a single prompt set cannot characterise CLIP semantics as a whole.
  5. THE PATCH LAYER IS A CHOICE.  hidden_states[-2] is what the project CLIPVisionEncoder emits
     (LLaVA-1.5 select_layer=-2); hidden_states[-1] is the true last encoder layer, reported as
     cs_alpha_last.  CLIP visual_projection was contrastively trained on the pooled CLS of the full
     tower, NOT on patch tokens, so applying it to patches is a defensible but unsupervised use of
     the projection: native here means web-scale pretrained, not used exactly as CLIP intended.
  6. ffiw IS EXCLUDED FROM ALL AGGREGATES.  It has a single video identity, so a per-domain linear
     head can latch onto identity/background rather than manipulation; its AUC is upward-biased and
     is reported only for completeness.
  7. THE NULL CONTROL IS NOT UNIQUE.  With a single pre-registered null prompt there are two
     non-degenerate ways to slot it in; both (nullA / nullB) are reported.  Neither is a perfect
     semantic-content-matched control -- an ideal one would use topic-matched prompts.
  8. y CONVENTION: 1=real, 0=fake.  All reported AUCs use positive = FAKE, matching _g16/run_g16.py
     and reproducing the recorded V anchors, so the numbers are directly comparable to the
     already-recorded ratio table.
  9. NO TRAINING OCCURRED.  This is a diagnostic probe: zero training budget consumed, no checkpoint
     changed, and no file outside vit_module/_g21/ touched.
 10. THE LABEL-SWAP CONTROL DID NOT MEET ITS PRE-REGISTERED EXPECTATION and this is reported as
     measured, not softened: it produced an AUC exactly EQUAL to the main arm rather than 1-AUC,
     because the swap is an exact global reflection to which AUC is invariant (see section C for the
     explicit numerical verification).  Treat that arm as an antisymmetry check, NOT as a test of
     sign/direction.  The NULL and RANDOM arms carry the semantic-control weight in this design.
 11. THE GATE IS A LITERAL PRE-REGISTERED RULE, NOT A GRADED VERDICT.  cs_alpha fails BOTH clauses,
     so the route is closed on this evidence.  That is a statement about this probe, not a proof that
     no text-conditioned architecture could ever help -- see caveats 1 and 3.
